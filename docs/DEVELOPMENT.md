# 个人博客开发流程文档

## 1. 开发目标

本项目是一个个人博客系统，核心目标是先把「可浏览、可搜索、可评论、可点赞、可收藏、可后台管理」这条主链路做稳，再逐步扩展体验细节。

## 2. 本地环境准备

### 2.1 基础依赖

- 前端：Node.js、npm
- 后端：Go
- 数据库：MySQL 8.x
- 缓存：Redis 7.x（可选）

### 2.2 环境变量

复制根目录的 `.env.example` 为 `.env`，并确认以下配置：

- `MYSQL_DSN`
- `REDIS_ADDR`
- `JWT_SECRET`
- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_USERNAME`
- `SMTP_PASSWORD`
- `SMTP_FROM`
- `FRONTEND_ORIGIN`
- `PORT`

验证码邮件建议使用管理员邮箱的 SMTP 发出，`SMTP_USERNAME` 和 `SMTP_FROM` 通常都填你的 QQ 邮箱地址，`SMTP_PASSWORD` 填授权码，不要填 QQ 登录密码。

### 2.3 启动依赖服务

如果使用 Docker：

```bash
docker compose up -d
```

如果手动启动，确保 MySQL 和 Redis 已可连接。

## 3. 开发顺序

推荐按下面顺序推进，减少前后端反复返工。

### 3.1 数据库设计

1. 先确认表结构和字段含义。
2. 先落 `database/schema.sql`。
3. 再让后端模型与 SQL 保持一致。
4. 最后补充索引、外键和默认值。

### 3.2 后端开发

1. 先定义数据模型和 DTO。
2. 再实现认证、文章、分类、评论、互动、后台管理接口。
3. 完成接口后补充缓存逻辑和权限控制。
4. 最后做日志、错误处理和基础校验。

### 3.3 前端开发

1. 先接通 API 层。
2. 再搭建首页、详情页、登录页、后台页。
3. 先完成功能，再做视觉细化。
4. 最后统一样式、移动端适配和交互反馈。

## 4. 日常开发流程

### 4.1 新功能开发

1. 明确功能目标和边界。
2. 先改后端数据结构和接口。
3. 再同步前端页面和交互。
4. 补充文档与验收说明。
5. 本地联调通过后再合并。

### 4.2 修改现有功能

1. 先确认是否影响接口契约。
2. 如果影响数据库，先改 SQL 和模型。
3. 如果影响前端展示，先更新 API 调用和类型定义。
4. 完成后统一跑构建和测试。

### 4.3 数据库变更

1. 优先更新 `database/schema.sql`。
2. 后端模型同步修改。
3. 如涉及历史数据，补充兼容策略。
4. 文档里记录新字段用途和约束。

## 5. 接口联调流程

1. 先启动后端。
2. 再启动前端。
3. 先验证健康检查接口。
4. 再验证登录注册。
5. 再验证文章列表、详情、评论、点赞、收藏。
6. 最后验证后台文章、分类、评论、用户管理。

## 6. 测试与验收

每次提交前至少完成以下检查：

- 前端构建通过：`npm run build`
- 后端测试通过：`go test ./...`
- 首页能正确展示分类、文章和热门内容
- 登录后评论、点赞、收藏可用
- 站长后台可创建、编辑、删除文章与分类
- 模糊搜索可命中标题、摘要、正文、标签
- 移动端页面不破版

## 7. 代码规范

- 前后端字段名保持一致，避免重复映射
- 接口返回统一使用 JSON
- 后端错误信息简短明确
- 前端优先做状态反馈，不要静默失败
- 样式尽量使用可复用的类名，不在页面内堆重复 CSS

## 8. 推荐提交节奏

建议按下面粒度提交：

- `docs`
- `backend auth`
- `backend articles`
- `frontend home`
- `frontend detail`
- `admin dashboard`
- `style polish`

## 9. 发布前检查

1. 配置文件齐全。
2. 数据库初始化脚本可执行。
3. 登录链路可用。
4. 站长权限生效。
5. 搜索、评论、点赞、收藏都已验证。
6. 首页和详情页在桌面与移动端都正常。
